# Threat model

Assets are personal API keys/session cookies, provider/store/upstream credentials, team identity and roles, audit attribution, store/platform data and Kubernetes access. Browser clients, external MCP clients, model outputs and registered upstream responses/descriptions are untrusted. [System design](system-design.md) describes the boundaries; [operations](operations.md) describes operator duties.

| Threat | Implemented module/package control | Remaining risk or required runtime proof |
|---|---|---|
| Stolen/reused personal key | M5 hashed keys, scoped owner authorization and revocation; M6 revalidates calls. | A stolen active key has that user's authority until revoked. Final real two-user flow M10. |
| Member crosses ownership boundary | M5 role/owner checks; current identity/server version checked before M6 dispatch. | Shared Woo credentials grant store authority to authorized tools; they do not create per-person Woo accounts. |
| Browser/provider secret leak | Browser only uses same-origin session API; static frontend has no Secret token; Secret-backed server env and dedicated Secret references. | Tool arguments/results can contain sensitive business data. Minimize logs and provider inputs; inspect final frontend bundle M8/M10. |
| CSRF/session confusion | M5 Secure cookies, exact Origin/Host and CSRF checks; HTTPS dashboard ingress. | Machine/browser certificate trust and final mount/configuration must be proven. Backend must not trust arbitrary forwarded headers. |
| Malicious descriptions/results and prompt injection | Bounded safe catalog/schema, no arbitrary URL fetching from results, same gateway permission checks, sequential bounded chat tools. | A model may choose a harmful authorized tool. Prompt wording is not an authorization boundary. |
| SSRF/DNS rebinding | M5 URL rules; M6 checks all DNS answers and numeric dials while retaining Host/SNI; no proxies/redirects/retries; bounded resolver/network/payloads. | NetworkPolicy is an additional layer, cannot name TLS hosts; CNI/DNAT behavior and API exceptions need live testing. |
| Duplicate write after timeout | M6 never replays; M7 stops on uncertain/connection/protocol result and rejects duplicate writes. | An operation may have happened when its response was lost. Audit finalization can fail; communicate uncertainty. |
| Arbitrary sibling Pod reaches upstream | Release Woo/Inventory only admit exact backend name/instance/component plus gateway marker; databases/internal Services have no public route. | Labels are not cryptographic identity against a cluster administrator; actual policy enforcement M10. |
| Kubernetes privilege escalation | Dedicated namespace Role only get/create/update/delete Secrets; backend token only backend; no ClusterRole/list/watch; nonroot/read-only/dropALL for Python/frontend components. | A compromised backend can act on its dynamic Secret namespace. Cluster/operator authority remains trusted. |
| Store/container privileges | Existing WordPress/MariaDB/PostgreSQL writable data paths preserved; probes/resources and no automatic API token. | Existing image privilege exceptions need review; NetworkPolicy does not encrypt internal HTTP or persistent disks. |
| Production proxy spoofing | WordPress release ingress restricted to verified Traefik; production Woo TLS keeps hostname/SNI/signature; no TLS bypass. | Must verify Traefik overwrites forwarded scheme/Host and retained wp-config honors trusted path. Internal final hop is plaintext. |
| Data loss/rollback confusion | Three PVCs and dynamic Secret namespace retained; coordinated private backups and isolated restore-first procedure. | Helm rollback cannot restore schemas/data/deleted credentials; local-path storage is a single-machine failure domain. |
| Supply chain/public handoff leak | Pinned dependencies, immutable deployment preflight, source-only staging and prohibited-file/sentinel checks; private handoff only. | Static scans cannot prove no unknown secret exists; operator reviews final archive/access before submission. |

Mandatory core controls are separate from optional hardening: no new service mesh, external secret manager, cert-manager automation, replicated database, multi-store platform or high-availability claim is introduced. M9 static checks do not prove live enforcement, real provider quality, restore success or VPS operation. M10 owns final composition and runtime verification.
